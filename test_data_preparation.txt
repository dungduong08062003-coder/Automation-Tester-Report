Making call

There are two group for API calls :

Group 1: APIs that begin with Execute.....

Task<RestResponse> ExecuteAsync(RestRequest request, CancellationToken token = default);

Task<RestResponse> ExecuteGetAsync(RestRequest request, CancellationToken token);

Task<RestResponse<T>> ExecuteAsync<T>(RestRequest request, CancellationToken token);

//.....

 

The method do not throw exceptions when the server returns HTTP errors(4xx,5xx)

Instead, we check respone.StatusCode, respone.IsSuccessful, respone.Content, Respone.ErrorException

 

 Group2: APIs that do not begin begin with execute...

 This Group has two types:

 return T (deserialize):

Task<T> GetAsync<T>(RestRequest request, CancellationToken token);

Task<T> PostAsync<T>(RestRequest request, CancellationToken token);

//..,....

these methods throw exceptions when the server error(4xx,5xx) because  RestSharp thorws a exception before returning RestResponse 

Use these methods  when you only care about valid data (happy path) and want to rely on exception flow for errors

       2. return RestResponse (no deserialize) but throw exception

 

Task<RestResponse> GetAsync(RestRequest request, CancellationToken token);

Task<RestResponse> PostAsync(RestRequest request, CancellationToken token);

//.......

These methods throw exceptions when a server error occurs, even if  the client is configured not to throw exceptions

Use these methods when need the raw response but still want to follow an exception-driven error-handling flow 

 

Handling Response 

All Execute{Method}Async function return an instance of RestResponse. Execute{Method}Async<T> return a generic instance of RestResponse<T> where T is the response
