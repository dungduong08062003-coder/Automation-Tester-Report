RESTful API:

REST stands for Representational State Transfer, it is  a way of designing systems so that applications can communicate each other over a network in a simple, low-dependency, and easily scalable way

REST defines 6 architectural constrains that a web service must follow to be considered RESTful. 

Client-server: The system clear divided into roles 

Client: Send request, display , Interface processing

Server : logic processing, data manage.

the two sides can develop and change independently

 

Stateless : Server no save the client's state between requests

each request must :

self-contained full information.

Independent of previous request.

Cacheable: the response from the server should indicate whether it can be cached or not 

Client or proxy can be cache response

 Helps reduce server load, increase performance

Uniform Interface

API must have the interface consistent, predictable, including:

Resource identified by URI

Use the standard HTTP method 

Data exchanged by representation(JSON /XML)

Format, naming, status code synchronize the whole system

layered System: the system can consist of multiple intermediate layer that the client does not need to know

Load balancer

gateway

Authentication Layer

Cache layer

the Client only know : "I send request, I receive response "

 

Code on demand (optional): the server can send the code back to the client for execution.
